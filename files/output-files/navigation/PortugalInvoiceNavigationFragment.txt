Below is a `Fragment` wrapper that hosts your Compose `PortugalInvoiceScreen` and uses `viewModels()` from the Android/Jetpack ViewModel API, so it can be used as a normal Navigation XML destination.

## 1) New fragment: `PortugalInvoiceNavigationFragment`

```kotlin
package ifac.td.taxi.ui.screen

import android.os.Bundle
import android.view.LayoutInflater
import android.view.View
import android.view.ViewGroup
import androidx.activity.compose.setContent
import androidx.compose.material3.MaterialTheme
import androidx.compose.ui.platform.ComposeView
import androidx.compose.ui.platform.ViewCompositionStrategy
import androidx.fragment.app.Fragment
import androidx.fragment.app.viewModels
import ifac.td.taxi.viewmodel.PortugalInvoiceComposeViewModel

class PortugalInvoiceNavigationFragment : Fragment() {

    private val viewModel: PortugalInvoiceComposeViewModel by viewModels()

    override fun onCreateView(
        inflater: LayoutInflater,
        container: ViewGroup?,
        savedInstanceState: Bundle?
    ): View {
        return ComposeView(requireContext()).apply {
            setViewCompositionStrategy(
                ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed
            )
            setContent {
                MaterialTheme {
                    PortugalInvoiceScreen(
                        viewModel = viewModel,
                        onNavigateBack = {
                            requireActivity().onBackPressedDispatcher.onBackPressed()
                        },
                        onNavigateToReceiptHistory = { tripId ->
                            val action =
                                HomeFragmentDirections.actionHomeFragmentToReceiptHistoryFragment()
                            // If you need tripId in ReceiptHistoryFragment, use the proper generated action/args.
                            parentFragmentManager.fragments // no-op placeholder
                        },
                        showHeader = false
                    )
                }
            }
        }
    }
}
```

## 2) Better version with `NavController` support

Since your composable already exposes navigation callbacks, the fragment can directly map those to the `NavController`:

```kotlin
package ifac.td.taxi.ui.screen

import android.os.Bundle
import android.view.View
import androidx.compose.material3.MaterialTheme
import androidx.compose.ui.platform.ComposeView
import androidx.compose.ui.platform.ViewCompositionStrategy
import androidx.fragment.app.Fragment
import androidx.fragment.app.viewModels
import androidx.navigation.fragment.findNavController
import ifac.td.taxi.viewmodel.PortugalInvoiceComposeViewModel

class PortugalInvoiceNavigationFragment : Fragment() {

    private val viewModel: PortugalInvoiceComposeViewModel by viewModels()

    override fun onCreateView(
        inflater: android.view.LayoutInflater,
        container: android.view.ViewGroup?,
        savedInstanceState: Bundle?
    ): View {
        return ComposeView(requireContext()).apply {
            setViewCompositionStrategy(
                ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed
            )
            setContent {
                MaterialTheme {
                    PortugalInvoiceScreen(
                        viewModel = viewModel,
                        onNavigateBack = {
                            findNavController().navigateUp()
                        },
                        onNavigateToReceiptHistory = { tripId ->
                            // Use your real generated action if ReceiptHistoryFragment expects args.
                            findNavController().navigate(
                                R.id.action_portugalInvoiceFragment_to_receiptHistoryFragment
                            )
                        },
                        showHeader = false
                    )
                }
            }
        }
    }
}
```

## 3) If you want to pass a `tripId` or other args

If your `PortugalInvoiceComposeViewModel` needs arguments from the nav graph, read them from `arguments` in the fragment and pass them into the ViewModel or its initializer. Example:

```kotlin
val tripId = arguments?.getLong("tripId") ?: 0L
```

Then either:
- call a `viewModel.init(tripId)` method, or
- use a custom `ViewModelProvider.Factory` if the ViewModel constructor requires parameters.

## 4) Add it to your nav graph

Replace the old fragment destination:

```xml
<fragment
    android:id="@+id/portugalInvoiceFragment"
    android:name="ifac.td.taxi.ui.screen.PortugalInvoiceNavigationFragment"
    android:label="PortugalInvoiceNavigationFragment"
    tools:layout="@layout/fragment_portugal_invoice">
    <action
        android:id="@+id/action_portugalInvoiceFragment_to_receiptHistoryFragment"
        app:destination="@id/receiptHistoryFragment"
        app:popUpTo="@id/homeFragment" />
</fragment>
```

## 5) Notes

- `viewModels()` is the correct choice for a Fragment-hosted Compose screen.
- `ComposeView` is the cleanest way to host your composable inside a Fragment.
- `ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed` prevents leaks.
- Keep navigation callbacks in the composable, but let the Fragment translate them to `NavController` actions.
