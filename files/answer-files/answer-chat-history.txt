QUESTION: How can I apply a common style and modifiers to all composables 
ANSWER:
In Jetpack Compose, the usual way to apply a common style or set of modifiers to many composables is to **centralize them in reusable wrappers, theme values, or extension functions** rather than trying to “globally” style every composable.

## 1) Use a custom theme for shared visual style
For things like colors, typography, shapes, and elevation, define them in your app theme:

```kotlin
@Composable
fun MyAppTheme(content: @Composable () -> Unit) {
    MaterialTheme(
        colorScheme = lightColorScheme(
            primary = Color(0xFF6200EE),
            secondary = Color(0xFF03DAC5)
        ),
        typography = Typography(
            bodyLarge = TextStyle(fontSize = 16.sp)
        ),
        shapes = Shapes(
            small = RoundedCornerShape(8.dp)
        ),
        content = content
    )
}
```

Then wrap your app:

```kotlin
MyAppTheme {
    AppContent()
}
```

This is the best way to apply a common **look and feel**.

---

## 2) Create reusable modifier chains
If you want the same padding, background, click behavior, etc., define a shared modifier:

```kotlin
val commonModifier = Modifier
    .padding(16.dp)
    .fillMaxWidth()
```

Use it in composables:

```kotlin
Text(
    text = "Hello",
    modifier = commonModifier
)
```

If you need it in many places, make it an extension:

```kotlin
fun Modifier.commonCardStyle() = this
    .padding(16.dp)
    .fillMaxWidth()
    .clip(RoundedCornerShape(12.dp))
    .background(Color.White)
```

Usage:

```kotlin
Box(modifier = Modifier.commonCardStyle()) {
    Text("Content")
}
```

---

## 3) Build wrapper composables for repeated layouts
If multiple composables should share the same container style, create a reusable composable:

```kotlin
@Composable
fun StyledContainer(
    modifier: Modifier = Modifier,
    content: @Composable () -> Unit
) {
    Box(
        modifier = modifier
            .padding(16.dp)
            .fillMaxWidth()
            .background(Color.LightGray, RoundedCornerShape(12.dp))
            .padding(16.dp)
    ) {
        content()
    }
}
```

Usage:

```kotlin
StyledContainer {
    Text("Inside styled container")
}
```

This is useful when the style is more than just a modifier chain.

---

## 4) Use `CompositionLocal` for app-wide defaults
If you want to provide shared values like spacing, corner radius, or default padding across the app, use `CompositionLocal`:

```kotlin
data class AppSpacing(
    val small: Dp = 8.dp,
    val medium: Dp = 16.dp,
    val large: Dp = 24.dp
)

val LocalAppSpacing = staticCompositionLocalOf { AppSpacing() }
```

Provide it:

```kotlin
CompositionLocalProvider(
    LocalAppSpacing provides AppSpacing()
) {
    AppContent()
}
```

Use it:

```kotlin
val spacing = LocalAppSpacing.current

Text(
    "Hello",
    modifier = Modifier.padding(spacing.medium)
)
```

---

## 5) Prefer passing modifiers into composables
A Compose best practice is to let composables accept a `modifier` parameter:

```kotlin
@Composable
fun MyButton(
    modifier: Modifier = Modifier,
    text: String
) {
    Button(
        onClick = { },
        modifier = modifier
    ) {
        Text(text)
    }
}
```

Then callers can apply common styling:

```kotlin
MyButton(
    modifier = Modifier
        .fillMaxWidth()
        .padding(8.dp),
    text = "Submit"
)
```

---

## Important note
You generally **cannot apply one modifier automatically to every composable globally** in Compose. Modifiers are meant to be attached explicitly to each composable or handled through:
- theme
- wrapper composables
- shared modifier extensions
- `CompositionLocal`

## Recommended approach
- **For colors/typography/shapes:** use `MaterialTheme`
- **For repeated modifier chains:** use `Modifier` extension functions
- **For repeated UI blocks:** use wrapper composables
- **For shared spacing/config:** use `CompositionLocal`

## 3) Create `CompositionLocal`s

This is how you make the style values globally accessible.

### `AppTheme.kt`
```kotlin
package com.example.app.ui.theme

import androidx.compose.runtime.Composable
import androidx.compose.runtime.Immutable
import androidx.compose.runtime.staticCompositionLocalOf
import androidx.compose.runtime.CompositionLocalProvider
import androidx.compose.material3.MaterialTheme

@Immutable
data class AppStyle(
    val colors: AppColors,
    val dimens: AppDimens
)

val LocalAppStyle = staticCompositionLocalOf {
    AppStyle(
        colors = LightAppColors,
        dimens = DefaultAppDimens
    )
}

@Composable
fun AppTheme(
    darkTheme: Boolean = false,
    content: @Composable () -> Unit
) {
    val colors = if (darkTheme) DarkAppColors else LightAppColors

    val appStyle = AppStyle(
        colors = colors,
        dimens = DefaultAppDimens
    )

    CompositionLocalProvider(
        LocalAppStyle provides appStyle
    ) {
        MaterialTheme(
            colorScheme = if (darkTheme) {
                androidx.compose.material3.darkColorScheme()
            } else {
                androidx.compose.material3.lightColorScheme()
            },
            typography = AppTypography,
            shapes = AppShapes,
            content = content
        )
    }
}
```

## 5) Create reusable `Modifier` extensions

These let you apply your app style consistently.

### `AppModifiers.kt`
```kotlin
package com.example.app.ui.modifiers

import androidx.compose.foundation.background
import androidx.compose.foundation.border
import androidx.compose.foundation.layout.padding
import androidx.compose.foundation.shape.RoundedCornerShape
import androidx.compose.ui.Modifier
import androidx.compose.ui.draw.clip
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.unit.dp
import com.example.app.ui.theme.LocalAppStyle

fun Modifier.appCardStyle(): Modifier {
    val style = LocalAppStyle.current
    return this
        .clip(RoundedCornerShape(style.dimens.cardRadius))
        .background(style.colors.surface)
}

fun Modifier.appScreenPadding(): Modifier {
    val style = LocalAppStyle.current
    return this.padding(style.dimens.screenPadding)
}

fun Modifier.appBorder(color: Color): Modifier {
    return this.border(1.dp, color, RoundedCornerShape(12.dp))
}
```

> Note: `Modifier` extensions can read `CompositionLocal` values if they are called from a composable context.  
> If you want to be strict, you can mark them `@Composable` when they depend on `LocalAppStyle.current`.

Example safer version:

```kotlin
@Composable
fun Modifier.appCardStyle(): Modifier {
    val style = LocalAppStyle.current
    return this
        .clip(RoundedCornerShape(style.dimens.cardRadius))
        .background(style.colors.surface)
}
```

## 6) Build reusable components using the theme

### `AppButton.kt`
```kotlin
package com.example.app.ui.components

import androidx.compose.foundation.layout.height
import androidx.compose.material3.Button
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import com.example.app.ui.theme.LocalAppStyle

@Composable
fun AppButton(
    text: String,
    onClick: () -> Unit,
    modifier: Modifier = Modifier
) {
    val style = LocalAppStyle.current

    Button(
        onClick = onClick,
        modifier = modifier.height(style.dimens.buttonHeight)
    ) {
        Text(text = text)
    }
}
```

### `AppCard.kt`
```kotlin
package com.example.app.ui.components

import androidx.compose.foundation.layout.Column
import androidx.compose.foundation.layout.padding
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import com.example.app.ui.modifiers.appCardStyle
import com.example.app.ui.theme.LocalAppStyle

@Composable
fun AppCard(
    title: String,
    body: String,
    modifier: Modifier = Modifier
) {
    val style = LocalAppStyle.current

    Column(
        modifier = modifier
            .appCardStyle()
            .padding(style.dimens.itemSpacing)
    ) {
        Text(text = title)
        Text(text = body)
    }
}
```

## 7) Use it in a screen

### `HomeScreen.kt`
```kotlin
package com.example.app.feature.home

import androidx.compose.foundation.layout.Arrangement
import androidx.compose.foundation.layout.Column
import androidx.compose.foundation.layout.fillMaxSize
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import com.example.app.ui.components.AppButton
import com.example.app.ui.components.AppCard
import com.example.app.ui.modifiers.appScreenPadding
import com.example.app.ui.theme.LocalAppStyle

@Composable
fun HomeScreen() {
    val style = LocalAppStyle.current

    Column(
        modifier = Modifier
            .fillMaxSize()
            .appScreenPadding(),
        verticalArrangement = Arrangement.spacedBy(style.dimens.itemSpacing)
    ) {
        AppCard(
            title = "Welcome",
            body = "This card uses global app styles."
        )

        AppButton(
            text = "Continue",
            onClick = { }
        )
    }
}
```

package com.example.app

import android.os.Bundle

import androidx.activity.compose.setContent

        }
    }
}

# How this works

## `Theme`
`AppTheme` is the root wrapper. It provides:
- Material theme values
- your custom app style values

## `CompositionLocal`
`LocalAppStyle` makes your app tokens available anywhere in the composable tree without passing them manually.

## `Modifier extensions`
These keep styling reusable and consistent:
- `appScreenPadding()`
- `appCardStyle()`
- `appBorder()`

---

# Recommended pattern

A clean pattern is:

- **Theme** = app-wide provider
- **CompositionLocal** = access to design tokens
- **Modifier extensions** = reusable layout/styling helpers
- **Components** = use the tokens, not hardcoded values

---

# Small improvement: separate tokens by category

If your app grows, split style into multiple locals:

```kotlin
val LocalAppColors = staticCompositionLocalOf { LightAppColors }
val LocalAppDimens = staticCompositionLocalOf { DefaultAppDimens }
```

Then provide them separately in `AppTheme`.

This is often better than one big `AppStyle` object if you want more flexibility.
