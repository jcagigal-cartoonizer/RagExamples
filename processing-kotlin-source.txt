QUESTION: I want to process some kotlin source files to create a list of all classes, composables and variables.
How can I do that?

ANSWER:
You can do this in a few ways, but the most reliable one is to **parse Kotlin source code with the Kotlin compiler API / PSI** instead of using regular expressions.

From your examples, you want to extract things like:

- **classes**: `ToolsViewModel`, `ComposeSharedViewModel`, `StatisticsViewModel`, etc.
- **composables**: usually functions annotated with `@Composable`
- **variables**: `private val TAG = ...`, `_tripListFlow`, `PAGE_SIZE`, etc.

## Recommended approach: use Kotlin PSI

Kotlin’s parser gives you an AST-like structure for each file, so you can inspect declarations properly.

### What to look for
- `KtClass` → class declarations
- `KtNamedFunction` with `@Composable` annotation → composable functions
- `KtProperty` → variables/properties

---

## Example using Kotlin PSI

You can build a small script or tool that:

1. Reads `.kt` files
2. Parses each file into PSI
3. Walks the declarations
4. Collects names of classes, composables, and variables

### Dependencies
If you’re doing this in a Kotlin/JVM project, add Kotlin compiler embeddable / PSI support, for example:

```kotlin
implementation("org.jetbrains.kotlin:kotlin-compiler-embeddable:<version>")
```

---

## Basic example

```kotlin
import org.jetbrains.kotlin.cli.jvm.compiler.KotlinCoreEnvironment
import org.jetbrains.kotlin.cli.jvm.compiler.toCoreEnvironment
import org.jetbrains.kotlin.config.CompilerConfiguration
import org.jetbrains.kotlin.config.JVMConfigurationKeys
import org.jetbrains.kotlin.com.intellij.openapi.Disposable
import org.jetbrains.kotlin.com.intellij.openapi.util.Disposer
import org.jetbrains.kotlin.psi.KtClass
import org.jetbrains.kotlin.psi.KtFile
import org.jetbrains.kotlin.psi.KtNamedFunction
import org.jetbrains.kotlin.psi.KtProperty
import org.jetbrains.kotlin.psi.KtPsiFactory
import org.jetbrains.kotlin.psi.KtAnnotationEntry
import java.io.File

fun main() {
    val disposable: Disposable = Disposer.newDisposable()
    val configuration = CompilerConfiguration()
    val environment = KotlinCoreEnvironment.createForProduction(
        disposable,
        configuration,
        org.jetbrains.kotlin.cli.jvm.compiler.EnvironmentConfigFiles.JVM_CONFIG_FILES
    )

    val sourceFile = File("src/main/java/ifac/td/taxi/viewmodel/ToolsViewModel.kt")
    val psiFile = KtPsiFactory(environment.project)
        .createFile(sourceFile.name, sourceFile.readText())

    val classes = mutableListOf<String>()
    val composables = mutableListOf<String>()
    val variables = mutableListOf<String>()

    psiFile.declarations.forEach { declaration ->
        when (declaration) {
            is KtClass -> classes.add(declaration.name ?: "<anonymous>")
            is KtNamedFunction -> {
                if (declaration.annotationEntries.any { it.shortName?.asString() == "Composable" }) {
                    composables.add(declaration.name ?: "<anonymous>")
                }
            }
            is KtProperty -> variables.add(declaration.name)
        }
    }

    println("Classes: $classes")
    println("Composables: $composables")
    println("Variables: $variables")

    Disposer.dispose(disposable)
}
```

## If you only need a simpler solution
If your goal is just to get a rough list and your codebase is not too complex, you can also use a **regex-based scan**:

- `class\s+(\w+)` for classes
- `@Composable\s+fun\s+(\w+)` for composables
- `val\s+(\w+)` / `var\s+(\w+)` for variables

But regex is fragile:
- it can miss multiline declarations
- it can match comments or strings
- it doesn’t understand Kotlin syntax

So for your input, PSI is much better.

## Best practice
If you want this for an actual codebase, I’d suggest:

1. **Walk all `.kt` files recursively**
2. **Parse each file with Kotlin PSI**
3. **Extract:**
   - class names
   - function names with `@Composable`
   - property names
4. **Write the result to JSON or CSV**

## Important note
If you want **all variables inside classes and functions**, not just top-level ones, you should recurse through the PSI tree instead of only checking `psiFile.declarations`.
