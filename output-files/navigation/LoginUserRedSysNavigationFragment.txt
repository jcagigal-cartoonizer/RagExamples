Below is a `Fragment` implementation that can replace `ifac.td.taxi.ui.screen.LoginUserRedSysFragment` as the navigation destination, while hosting your Compose UI and using `viewModels()` for the ViewModel initialization.

It preserves the same navigation action:

`R.id.action_loginUserRedSysFragment_to_changePasswordRedSysFragment`

and uses only Android + Jetpack Compose APIs.

---

## `LoginUserRedSysNavigationFragment.kt`

```kotlin
package ifac.td.taxi.ui.screen

import android.os.Bundle
import android.view.LayoutInflater
import android.view.View
import android.view.ViewGroup
import android.widget.Toast
import androidx.compose.foundation.layout.*
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.platform.ComposeView
import androidx.compose.ui.platform.LocalContext
import androidx.compose.ui.res.stringResource
import androidx.compose.ui.unit.dp
import androidx.fragment.app.Fragment
import androidx.fragment.app.viewModels
import androidx.lifecycle.Lifecycle
import androidx.lifecycle.compose.collectAsStateWithLifecycle
import androidx.lifecycle.compose.LocalLifecycleOwner
import androidx.lifecycle.lifecycleScope
import androidx.lifecycle.repeatOnLifecycle
import androidx.navigation.NavController
import androidx.navigation.fragment.findNavController
import ifac.td.taxi.R
import ifac.td.taxi.viewmodel.LoginUserRedSysComposeViewModel
import kotlinx.coroutines.launch

class LoginUserRedSysNavigationFragment : Fragment() {

    private val viewModel: LoginUserRedSysComposeViewModel by viewModels()

    override fun onCreateView(
        inflater: LayoutInflater,
        container: ViewGroup?,
        savedInstanceState: Bundle?
    ): View {
        return ComposeView(requireContext()).apply {
            setContent {
                val navController = findNavController()

                LoginUserRedSysScreen(
                    viewModel = viewModel,
                    navController = navController,
                    onBack = {
                        requireActivity().onBackPressedDispatcher.onBackPressed()
                    },
                    onNavigateToChangePassword = {
                        navController.navigate(
                            R.id.action_loginUserRedSysFragment_to_changePasswordRedSysFragment
                        )
                    }
                )
            }
        }
    }
}
```

---

## Notes

### 1) Use this fragment in the nav graph
Change the destination from:

```xml
android:name="ifac.td.taxi.ui.screen.LoginUserRedSysFragment"
```

to:

```xml
android:name="ifac.td.taxi.ui.screen.LoginUserRedSysNavigationFragment"
```

So your nav graph entry becomes:

```xml
<fragment
    android:id="@+id/loginUserRedSysFragment"
    android:name="ifac.td.taxi.ui.screen.LoginUserRedSysNavigationFragment"
    android:label="LoginUserRedSysFragment"
    tools:layout="@layout/fragment_login_user_red_sys">
    <action
        android:id="@+id/action_loginUserRedSysFragment_to_changePasswordRedSysFragment"
        app:destination="@id/changePasswordRedSysFragment" />
</fragment>
```

---

## 2) Your existing composable can be reused as-is
Your `LoginUserRedSysScreen(...)` composable already handles:

- collecting `uiState`
- collecting `uiEffect`
- showing the dialog
- navigating back
- navigating to change password

So the fragment above simply hosts it.

---

## 3) Important
Because you asked to use `viewModels()` instead of a Compose ViewModel helper, the fragment now owns the ViewModel through:

```kotlin
private val viewModel: LoginUserRedSysComposeViewModel by viewModels()
```

This is the standard AndroidX Fragment API.

---

## 4) If you want the fragment to be even more minimal
Since the composable already takes care of `findNavController()`-based navigation, the fragment can also be kept very small, but the version above is the safest and clearest.
