## What each part is for

### `MainActivity.kt`
Hosts the Compose UI with `setContent {}` and starts the app.

### `ui/`
Contains only Compose-related code:
- `screens/` for full-screen composables
- `components/` for reusable UI pieces
- `theme/` for Material styling
- `navigation/` for Compose Navigation

### `data/`
Contains app data and langchain4j integration:
- `repository/` abstracts the AI/chat source
- `langchain4j/` holds the assistant interface and prompt templates
- `model/` holds UI/data state models

### `viewmodel/`
Bridges UI and repository:
- handles user input
- calls langchain4j
- exposes state to Compose

### `di/`
If using dependency injection, place module/wiring here.

## Minimal langchain4j-oriented files

### `data/langchain4j/AssistantService.kt`
```kotlin
package com.example.migration.data.langchain4j

interface AssistantService {
    fun chat(prompt: String): String
}
```

### `data/langchain4j/PromptTemplates.kt`
```kotlin
package com.example.migration.data.langchain4j

object PromptTemplates {
    const val MIGRATION_HELP = """
        You are an Android migration assistant.
        Help migrate Jetpack Views to Jetpack Compose.
        Focus only on Android and Compose.
    """
}
```

### `data/repository/ChatRepository.kt`
```kotlin
package com.example.migration.data.repository

import com.example.migration.data.langchain4j.AssistantService

class ChatRepository(
    private val assistantService: AssistantService
) {
    fun sendPrompt(prompt: String): String {
        return assistantService.chat(prompt)
    }
}
```

### `viewmodel/ChatViewModel.kt`
```kotlin
package com.example.migration.viewmodel

import androidx.lifecycle.ViewModel
import com.example.migration.data.repository.ChatRepository

class ChatViewModel(
    private val repository: ChatRepository
) : ViewModel() {

    fun askMigrationQuestion(prompt: String): String {
        return repository.sendPrompt(prompt)
    }
}
```

## Migration guidance

For a clean **Views → Compose** migration:
1. Keep your old XML/View code isolated.
2. Add Compose screens gradually.
3. Move UI state into `ViewModel`.
4. Put AI prompt logic in `data/langchain4j/`.
5. Let Compose observe state and render results.

## Compose version
```kotlin
@Composable
fun HomeScreen(onDetailsClick: () -> Unit) {
    Column(
        modifier = Modifier
            .fillMaxSize()
            .padding(16.dp)
    ) {
        Text(
            text = "VeggieVille Friends",
            fontSize = 24.sp,
            fontWeight = FontWeight.Bold
        )

        Spacer(modifier = Modifier.height(16.dp))

        Image(
            painter = painterResource(id = R.drawable.charlie_carrot),
            contentDescription = "Charlie the carrot",
            modifier = Modifier.size(120.dp)
        )

        Spacer(modifier = Modifier.height(8.dp))

        Text(text = "Charlie is cheerful and always optimistic.")

        Spacer(modifier = Modifier.height(16.dp))

        Button(onClick = onDetailsClick) {
            Text("Meet Charlie")
        }
    }
}
```

## What changed
- `LinearLayout` → `Column`
- `TextView` → `Text`
- `ImageView` → `Image`
- `Button` stays a `Button`, but click handling becomes a lambda (`onClick`)
- No `findViewById`; state and actions are passed directly

## Compose version
```kotlin
@Composable
fun CharacterDetailScreen(
    name: String,
    story: String,
    onBackClick: () -> Unit
) {
    Column(
        modifier = Modifier
            .fillMaxSize()
            .verticalScroll(rememberScrollState())
            .padding(16.dp)
    ) {
        Text(
            text = name,
            fontSize = 22.sp,
            fontWeight = FontWeight.Bold
        )

        Spacer(modifier = Modifier.height(8.dp))

        Text(text = story)

        Spacer(modifier = Modifier.height(16.dp))

        Button(onClick = onBackClick) {
            Text("Back")
        }
    }
}
```

## What changed
- `ScrollView + LinearLayout` → `Column + verticalScroll(...)`
- Screen data is passed as parameters (`name`, `story`)
- Easier to reuse for Bella, Timmy, and Percy

# 5) Navigation example in Compose

In XML, each screen often had its own Activity. In Compose, you usually navigate between composables.

```kotlin
@Composable
fun VeggieVilleApp() {
    val navController = rememberNavController()

    NavHost(navController = navController, startDestination = "home") {
        composable("home") {
            HomeScreen(
                onDetailsClick = { navController.navigate("charlie") }
            )
        }
        composable("charlie") {
            CharacterDetailScreen(
                name = "Charlie the Carrot",
                story = "A radiant carrot with an infectious laugh and warm personality.",
                onBackClick = { navController.popBackStack() }
            )
        }
        composable("feast") {
            FeastScreen(
                leavesCount = "",
                onLeavesCountChange = {},
                onHostFeast = { navController.navigate("victory") }
            )
        }
        composable("victory") {
            VictoryScreen(
                onCelebrateClick = { /* celebrate */ }
            )
        }
    }
}
```

# Migration summary

## XML → Compose mapping
- `Activity + XML layout` → `Composable screen`
- `findViewById` → `remember { mutableStateOf(...) }` or parameters
- `EditText` → `TextField`
- `ImageView` → `Image`
- `LinearLayout / RelativeLayout` → `Column / Row / Box`
- `ScrollView` → `verticalScroll`
- `Intent navigation` → `Navigation Compose`

---

# Practical migration strategy
If you were migrating the VeggieVille app screen by screen, a good order would be:

1. **Start with HomeScreen**
   - simplest layout
   - replace XML with `setContent { HomeScreen() }`

2. **Move CharacterDetailScreen next**
   - refactor repeated character UI into reusable composables

3. **Convert FeastScreen**
   - introduces input state and `TextField`

4. **Finish with VictoryScreen**
   - demonstrates alignment and celebration UI

5. **Replace XML navigation**
   - move from Activities to Compose Navigation, if desired

---

# Final takeaway
A screen-by-screen migration from XML to Compose means:
- converting each XML layout into a composable function,
- replacing imperative view logic with declarative state,
- and gradually moving navigation and UI state into Compose.
