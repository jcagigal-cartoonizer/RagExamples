Below is a **Fragment wrapper** named:

`ifac.td.taxi.ui.screen.RequestStandReinforcementNavigationFragment`

It uses:

- `viewModels()` from **AndroidX Fragment**
- your **Compose screen** `RequestStandReinforcementScreen(...)`
- **NavArgs** for the same arguments as the original fragment
- only **Android + Jetpack Compose** references in the Fragment UI layer

> Note: this Fragment assumes your `RequestStandReinforcementViewModel` exposes the same state/actions you already use for the Compose screen.

---

## Fragment implementation

```kotlin
package ifac.td.taxi.ui.screen

import android.os.Bundle
import android.view.LayoutInflater
import android.view.View
import android.view.ViewGroup
import androidx.compose.ui.platform.ComposeView
import androidx.compose.ui.platform.ViewCompositionStrategy
import androidx.fragment.app.Fragment
import androidx.fragment.app.viewModels
import androidx.navigation.fragment.navArgs
import ifac.td.taxi.viewmodel.RequestStandReinforcementViewModel
import ifac.td.taxi.ui.screen.RequestStandReinforcementAction
import ifac.td.taxi.ui.screen.RequestStandReinforcementScreen
import ifac.td.taxi.ui.screen.RequestStandReinforcementUiState

class RequestStandReinforcementNavigationFragment : Fragment() {

    private val viewModel: RequestStandReinforcementViewModel by viewModels()
    private val safeArgs: RequestStandReinforcementNavigationFragmentArgs by navArgs()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // If your ViewModel needs the args to initialize state, do it here or in onViewCreated.
        viewModel.onScreenStarted(
            idMacrozone = safeArgs.idMacrozone,
            idZone = safeArgs.idZone,
            isInFavourites = safeArgs.isInFavourites
        )
    }

    override fun onDestroy() {
        super.onDestroy()
        viewModel.onScreenStopped()
    }

    override fun onCreateView(
        inflater: LayoutInflater,
        container: ViewGroup?,
        savedInstanceState: Bundle?
    ): View {
        return ComposeView(requireContext()).apply {
            setViewCompositionStrategy(
                ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed
            )
            setContent {
                RequestStandReinforcementScreen(
                    uiState = viewModel.uiState,
                    onAction = ::handleAction
                )
            }
        }
    }

    private fun handleAction(action: RequestStandReinforcementAction) {
        when (action) {
            RequestStandReinforcementAction.CancelClicked -> {
                requireActivity().onBackPressedDispatcher.onBackPressed()
            }

            RequestStandReinforcementAction.AddFavouriteClicked -> {
                viewModel.addZoneToFavourites(safeArgs.idMacrozone, safeArgs.idZone)
                requireActivity().onBackPressedDispatcher.onBackPressed()
            }

            RequestStandReinforcementAction.RemoveFavouriteClicked -> {
                viewModel.removeZoneFromFavourites(safeArgs.idMacrozone, safeArgs.idZone)
                requireActivity().onBackPressedDispatcher.onBackPressed()
            }

            is RequestStandReinforcementAction.ReinforcementClicked -> {
                viewModel.sendReinforcementRequest(
                    safeArgs.idMacrozone,
                    safeArgs.idZone,
                    action.number
                )
                requireActivity().onBackPressedDispatcher.onBackPressed()
            }

            RequestStandReinforcementAction.DialogConfirmed -> {
                viewModel.onDialogConfirmed()
            }

            RequestStandReinforcementAction.DialogDismissed -> {
                viewModel.onDialogDismissed()
            }
        }
    }
}
```

## Important note about `viewModels()`

`by viewModels()` creates the ViewModel with the default `Fragment` factory.

So this works if your `RequestStandReinforcementViewModel`:

- has a no-arg constructor, or
- uses AndroidX `SavedStateHandle` / default factory-compatible construction, or
- is provided via a custom `ViewModelProvider.Factory`

If your ViewModel currently depends on Koin injection, Hilt, or constructor parameters, you’ll need to supply a proper factory. But since you asked specifically for `viewModels()`, the Fragment above uses that.

---

## If your ViewModel exposes `StateFlow` / `LiveData`

If `uiState` is not a plain property, use Compose collection inside `setContent`, for example:

```kotlin
setContent {
    val uiState = viewModel.uiState.collectAsStateWithLifecycle().value
    RequestStandReinforcementScreen(
        uiState = uiState,
        onAction = ::handleAction
    )
}
```

That requires lifecycle compose runtime, but it is still Jetpack Compose / AndroidX.

## Matching the original behavior

This Fragment preserves the original screen behavior:

- Cancel -> navigate back
- Add favourites -> add zone, then back
- Remove favourites -> remove zone, then back
- Reinforcement buttons -> send request, then back
- Uses `navArgs()` to read:
  - `idMacrozone`
  - `idZone`
  - `isInFavourites`
