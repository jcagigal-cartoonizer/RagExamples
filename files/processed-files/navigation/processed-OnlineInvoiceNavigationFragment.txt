## `OnlineInvoiceNavigationFragment.kt`
```kotlin
package ifac.td.taxi.ui.screen
// # Block 4-1: import android.os.Bundle
import android.os.Bundle
import android.view.LayoutInflater
import android.view.View
import android.view.ViewGroup
import androidx.compose.material3.MaterialTheme
import androidx.compose.ui.platform.ComposeView
import androidx.compose.ui.platform.ViewCompositionStrategy
import androidx.fragment.app.Fragment
import androidx.fragment.app.viewModels
import androidx.navigation.fragment.findNavController
import androidx.navigation.fragment.navArgs
import ifac.td.taxi.viewmodel.OnlineInvoiceViewModel
class OnlineInvoiceNavigationFragment : Fragment() {
    private val viewModel: OnlineInvoiceViewModel by viewModels()
    private val args: OnlineInvoiceNavigationFragmentArgs by navArgs()
    override fun onCreateView(
        inflater: LayoutInflater,
        container: ViewGroup?,
        savedInstanceState: Bundle?
    ): View {
        return ComposeView(requireContext()).apply {
            setViewCompositionStrategy(
                ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed
            )
            setContent {
                MaterialTheme {
                    OnlineInvoiceScreen(
                        tripId = args.tripId,
                        navController = findNavController(),
                        viewModel = viewModel
                    )
                }
            }
        }
    }
}
```

## Notes
### 1. `viewModels()` vs Compose `viewModel()`
```kotlin
private val viewModel: OnlineInvoiceViewModel by viewModels()
```
### 2. `navArgs()`
```kotlin
private val args: OnlineInvoiceNavigationFragmentArgs by navArgs()
```
### 3. `findNavController()`
```kotlin
navController = findNavController()
```

## If you want it even closer to your old Fragment behavior
Your old XML-based Fragment was also showing dialogs and handling loading via Views.  
Your Compose screen already appears to handle this with `uiState.dialogState`, `uiState.isLoading`, and effects, so the Fragment wrapper above is enough.
1. a version using a **Koin `viewModel()`** equivalent in Fragment,
2. a version that uses **`setContent` directly in your existing Fragment class** without creating a new one,
3. or the matching **`OnlineInvoiceViewModel` constructor / factory setup** so `by viewModels()` works correctly with arguments.
