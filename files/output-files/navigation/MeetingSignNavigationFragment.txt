Below is a View-based navigation **Fragment wrapper** that hosts your existing **Compose screen** and can be used as the destination class instead of the old XML/View `MeetingSignFragment`.

It uses:

- `by viewModels()` for the ViewModel
- plain Android + Jetpack Compose APIs
- Navigation Component safe args
- lifecycle-aware effect collection
- a Compose `MeetingSignScreen(...)` call inside `setContent`

---

## 1) New Fragment: `MeetingSignNavigationFragment`

```kotlin
package ifac.td.taxi.ui.screen

import android.content.pm.ActivityInfo
import android.os.Bundle
import android.view.LayoutInflater
import android.view.View
import android.view.ViewGroup
import androidx.activity.compose.setContent
import androidx.fragment.app.Fragment
import androidx.fragment.app.viewModels
import androidx.lifecycle.Lifecycle
import androidx.lifecycle.flowWithLifecycle
import androidx.lifecycle.lifecycleScope
import androidx.navigation.fragment.findNavController
import androidx.navigation.fragment.navArgs
import ifac.td.taxi.R
import ifac.td.taxi.viewmodel.MainActivityViewModel
import ifac.td.taxi.compose.viewmodel.MeetingSignComposeViewModel
import kotlinx.coroutines.flow.collectLatest
import kotlinx.coroutines.launch

class MeetingSignNavigationFragment : Fragment() {

    private val viewModel: MeetingSignComposeViewModel by viewModels()
    private val sharedViewModel: MainActivityViewModel by viewModels({ requireActivity() })
    private val safeArgs: MeetingSignNavigationFragmentArgs by navArgs()

    override fun onCreateView(
        inflater: LayoutInflater,
        container: ViewGroup?,
        savedInstanceState: Bundle?
    ): View {
        requireActivity().requestedOrientation =
            ActivityInfo.SCREEN_ORIENTATION_LANDSCAPE

        return androidx.compose.ui.platform.ComposeView(requireContext()).apply {
            setContent {
                MeetingSignScreen(
                    navController = findNavController(),
                    viewModel = viewModel,
                    textColor = safeArgs.textColor,
                    backgroundColor = safeArgs.backgroundColor,
                    fromDispatch = sharedViewModel.tripFlow.value?.fromDispatch == true,
                    isInSettings = findNavController().currentDestination?.parent?.id == R.id.settings,
                    onNavigateBack = { findNavController().navigateUp() },
                    onNavigateToInfoDispatch = {
                        findNavController().navigate(R.id.action_meetingSignFragment_to_infoDispatchFragment)
                    },
                    onShowToast = { resId ->
                        // Replace with your app's toast mechanism if desired.
                        // Example:
                        // Toast.makeText(requireContext(), getString(resId), Toast.LENGTH_SHORT).show()
                    }
                )
            }
        }
    }

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        // If your ViewModel needs initialization from args/environment, do it here if needed.
        // Example:
        // viewModel.setEnvironment(...)
    }
}
```

## 2) NavArgs class name

Because this fragment is named `MeetingSignNavigationFragment`, the generated Safe Args class will be:

```kotlin
MeetingSignNavigationFragmentArgs
```

So your navigation XML should point to this fragment class.

---

## 3) Update navigation XML

Replace:

```xml
android:name="ifac.td.taxi.ui.screen.MeetingSignFragment"
```

with:

```xml
android:name="ifac.td.taxi.ui.screen.MeetingSignNavigationFragment"
```

For example:

```xml
<fragment
    android:id="@+id/meetingSignFragment"
    android:name="ifac.td.taxi.ui.screen.MeetingSignNavigationFragment"
    android:label="MeetingSignFragment">
    <argument
        android:name="textColor"
        app:argType="integer" />
    <argument
        android:name="backgroundColor"
        app:argType="integer" />
    <action
        android:id="@+id/action_meetingSignFragment_to_infoDispatchFragment"
        app:destination="@id/infoDispatchFragment"
        app:popUpTo="@id/infoDispatchFragment" />
</fragment>
```

And similarly for:

```xml
android:id="@+id/meetingSignFragment2"
```

if you still need the second entry.

## 4) Notes about the Compose screen you already have

Your existing composable:

```kotlin
@Composable
fun MeetingSignScreen(
    navController: NavController,
    viewModel: MeetingSignComposeViewModel,
    textColor: Int,
    backgroundColor: Int,
    fromDispatch: Boolean,
    isInSettings: Boolean,
    onNavigateBack: () -> Unit,
    onNavigateToInfoDispatch: () -> Unit,
    onShowToast: (Int) -> Unit,
)
```

is already suitable for this fragment wrapper.

### Important
Your composable currently contains effect collection and dialog state handling, so the fragment only needs to:
- create the ViewModel
- supply args and callbacks
- host the composable

## 5) Recommended small adjustment

Inside the composable, if you are using:

```kotlin
LaunchedEffect(Unit) {
    lifecycleOwner.lifecycle.repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.effects.collect { ... }
    }
}
```

that is fine, but in Compose it is often cleaner to collect directly with `collectLatest` in a `LaunchedEffect(viewModel)` or use `flowWithLifecycle`.

Since you asked for the Fragment replacement, I did not change your screen logic.

---

## 6) If you want it fully ViewModel-safe with `by viewModels()`

If your `MeetingSignComposeViewModel` needs constructor dependencies, `by viewModels()` will still work only if you already have a `ViewModelProvider.Factory` configured by your app or DI setup.

If not, you’ll need a factory, but the fragment usage stays the same.
