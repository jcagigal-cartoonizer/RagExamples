Below is a clean `Fragment` wrapper that hosts your Compose `BluetoothDiscoveryScreen` and can be used in the Navigation XML instead of the old `BluetoothDiscoveryFragment`.

It uses:

- `viewModels()` for the ViewModel
- only Android + Jetpack Compose / Jetpack Navigation / Lifecycle APIs
- a fragment name exactly as requested:  
  `ifac.td.taxi.ui.screen.BluetoothDiscoveryNavigationFragment`

## 2) Compose route inside the Fragment

This is the Compose bridge that plugs your existing `BluetoothDiscoveryScreen` into the Fragment.

```kotlin
package ifac.td.taxi.ui.screen

import android.content.Intent
import androidx.compose.runtime.Composable
import androidx.compose.runtime.LaunchedEffect
import androidx.lifecycle.compose.collectAsStateWithLifecycle
import androidx.navigation.NavController
import androidx.fragment.app.Fragment
import androidx.lifecycle.viewmodel.compose.viewModel
import ifac.td.taxi.compose.viewmodel.BluetoothDiscoveryComposeViewModel
import ifac.td.taxi.ui.screen.BluetoothDiscoveryScreen

@Composable
fun BluetoothDiscoveryNavigationRoute(
    viewModel: BluetoothDiscoveryComposeViewModel,
    navBack: () -> Unit,
    onRequestBluetoothPermission: (String) -> Unit,
    onRequestLocationPermission: (String) -> Unit,
    onStartActivity: (Intent) -> Unit,
    onConnectTaximeter: () -> Unit,
) {
    BluetoothDiscoveryScreen(
        navBack = navBack,
        onRequestBluetoothPermission = onRequestBluetoothPermission,
        onRequestLocationPermission = onRequestLocationPermission,
        onStartActivity = onStartActivity,
        onConnectTaximeter = onConnectTaximeter,
        viewModel = viewModel
    )
}
```

## 3) Important note about `viewModels()` and the ViewModel type

Your Compose screen currently expects:

```kotlin
viewModel: BluetoothDiscoveryComposeViewModel
```

So the Fragment must obtain **that same ViewModel type** with `viewModels()`:

```kotlin
private val viewModel: BluetoothDiscoveryComposeViewModel by viewModels()
```

If your existing DI setup requires a custom factory, then you’d need to provide one to `viewModels(factoryProducer = { ... })`. But since you asked to use only Android + Jetpack Compose references, the simplest version above assumes the ViewModel has a default constructor or is otherwise factory-provided by your app setup.

## 4) Better minimal Fragment version

If you want the Fragment to be as small as possible, this is enough:

```kotlin
package ifac.td.taxi.ui.screen

import android.content.Intent
import android.os.Bundle
import android.view.View
import androidx.compose.material3.MaterialTheme
import androidx.compose.ui.platform.ComposeView
import androidx.compose.ui.platform.ViewCompositionStrategy
import androidx.fragment.app.Fragment
import androidx.fragment.app.viewModels
import ifac.td.taxi.compose.viewmodel.BluetoothDiscoveryComposeViewModel

class BluetoothDiscoveryNavigationFragment : Fragment() {

    private val viewModel: BluetoothDiscoveryComposeViewModel by viewModels()

    override fun onCreateView(
        inflater: android.view.LayoutInflater,
        container: android.view.ViewGroup?,
        savedInstanceState: Bundle?
    ): View {
        return ComposeView(requireContext()).apply {
            setViewCompositionStrategy(
                ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed
            )
            setContent {
                MaterialTheme {
                    BluetoothDiscoveryScreen(
                        navBack = { requireActivity().onBackPressedDispatcher.onBackPressed() },
                        onRequestBluetoothPermission = { },
                        onRequestLocationPermission = { },
                        onStartActivity = { intent: Intent -> startActivity(intent) },
                        onConnectTaximeter = { },
                        viewModel = viewModel
                    )
                }
            }
        }
    }
}
```

```xml
    android:label="DiscoveryChannelFragment"
    tools:layout="@layout/fragment_bluetooth_discovery" />
```

with:

```xml
<fragment
    android:id="@+id/discoveryChannelFragment"
    android:name="ifac.td.taxi.ui.screen.BluetoothDiscoveryNavigationFragment"
    android:label="DiscoveryChannelFragment" />
```

You can remove `tools:layout` because this Fragment creates its UI directly in Compose.

## 6) If you want it to behave more like your old Fragment

Your old fragment did a lot more than only UI rendering:
- permission checks
- Bluetooth enable dialog
- GPS enable dialog
- observing discovery flows
- managing selected devices and saved devices
- calling `connectTaximeter()`
- interacting with a shared `MainActivityViewModel`

If your `BluetoothDiscoveryComposeViewModel` already contains that logic, the wrapper above is enough.

If not, then the Fragment should also:
- observe permission state
- dispatch permission requests
- forward activity result / settings intents
- connect to a shared activity ViewModel if needed
