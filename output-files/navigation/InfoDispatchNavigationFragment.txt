Below is a clean `Fragment` wrapper that hosts your existing `InfoDispatchScreen` composable and can be used as a navigation destination instead of the old `InfoDispatchFragment`.

It uses:

- `viewModels()` for the `ViewModel`
- only Android + Jetpack Compose APIs in the fragment layer
- `ComposeView` to render the composable
- `NavController` from the Fragment host

---

## 1) New Fragment: `InfoDispatchNavigationFragment`

```kotlin
package ifac.td.taxi.ui.screen

import android.os.Bundle
import android.view.LayoutInflater
import android.view.View
import android.view.ViewGroup
import androidx.activity.compose.setContent
import androidx.compose.material3.MaterialTheme
import androidx.compose.ui.platform.ComposeView
import androidx.compose.ui.platform.ViewCompositionStrategy
import androidx.fragment.app.Fragment
import androidx.fragment.app.viewModels
import androidx.navigation.fragment.findNavController
import ifac.td.taxi.compose.viewmodel.InfoDispatchComposeViewModel

class InfoDispatchNavigationFragment : Fragment() {

    private val viewModel: InfoDispatchComposeViewModel by viewModels()

    override fun onCreateView(
        inflater: LayoutInflater,
        container: ViewGroup?,
        savedInstanceState: Bundle?
    ): View {
        return ComposeView(requireContext()).apply {
            setViewCompositionStrategy(
                ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed
            )
            setContent {
                MaterialTheme {
                    InfoDispatchScreen(
                        navController = findNavController(),
                        viewModel = viewModel
                    )
                }
            }
        }
    }
}
```

---

## 2) Update your navigation XML

Replace the old destination:

```xml
<fragment
    android:id="@+id/infoDispatchFragment"
    android:name="ifac.td.taxi.ui.screen.InfoDispatchFragment"
    android:label="InfoDispatchFragment"
    tools:layout="@layout/fragment_info_dispatch">
```

with:

```xml
<fragment
    android:id="@+id/infoDispatchFragment"
    android:name="ifac.td.taxi.ui.screen.InfoDispatchNavigationFragment"
    android:label="InfoDispatchNavigationFragment">
```

You can keep the same `id="@+id/infoDispatchFragment"` so the rest of your navigation graph does not need to change.

---

## 3) Important note about your composable

Your current composable already works as the UI layer:

```kotlin
@Composable
fun InfoDispatchScreen(
    navController: NavController,
    viewModel: InfoDispatchComposeViewModel
)
```

So the fragment only needs to host it.

If you want, you can also make the composable more fragment-friendly by avoiding direct navigation strings and using `NavDirections` where possible, but it is not required for this migration.

---

## 4) Why this works

- `Fragment` remains the navigation destination for the XML nav graph.
- The UI is fully Compose-based.
- `viewModels()` is used as requested.
- `findNavController()` gives the fragment’s navigation controller to the composable.

---

## 5) Optional improvement: use a dedicated Compose theme

If you already have your app theme composable, replace:

```kotlin
MaterialTheme {
    InfoDispatchScreen(...)
}
```

with your own theme, for example:

```kotlin
TaxiTheme {
    InfoDispatchScreen(
        navController = findNavController(),
        viewModel = viewModel
    )
}
```

---

## 6) Optional: if your ViewModel needs a factory

If `InfoDispatchComposeViewModel` has constructor parameters, then `by viewModels()` alone may not be enough. In that case you would need a factory. But if it has an empty constructor or DI support through default ViewModel creation, the code above is enough.
