Below is a `Fragment` you can use as a Navigation destination instead of `ifac.td.taxi.ui.screen.PermissionsFragment`, but hosting your `PermissionsScreen` composable.

It uses:

- `viewModels()` for the ViewModel
- Jetpack Compose inside a Fragment
- only Android / Jetpack Compose / Navigation references
- `navArgs()` to read `permissionType`
- `ComposeView` as the fragment UI container

---

## `PermissionsNavigationFragment.kt`

```kotlin
package ifac.td.taxi.ui.screen

import android.os.Bundle
import android.view.LayoutInflater
import android.view.View
import android.view.ViewGroup
import androidx.compose.runtime.collectAsState
import androidx.compose.runtime.getValue
import androidx.compose.ui.platform.ComposeView
import androidx.compose.ui.platform.ViewCompositionStrategy
import androidx.fragment.app.Fragment
import androidx.fragment.app.viewModels
import androidx.navigation.fragment.navArgs
import ifac.td.taxi.viewmodel.PermissionsViewModel
import ifac.td.taxi.ui.theme.TaxiTheme // replace with your app theme if different

class PermissionsNavigationFragment : Fragment() {

    private val viewModel: PermissionsViewModel by viewModels()
    private val args: PermissionsNavigationFragmentArgs by navArgs()

    override fun onCreateView(
        inflater: LayoutInflater,
        container: ViewGroup?,
        savedInstanceState: Bundle?
    ): View {
        return ComposeView(requireContext()).apply {
            setViewCompositionStrategy(
                ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed
            )

            setContent {
                TaxiTheme {
                    val uiState by viewModel.uiState.collectAsState()

                    PermissionsScreen(
                        uiState = uiState,
                        safePermissionType = args.permissionType,
                        onEvent = { event ->
                            viewModel.onEvent(event)
                        }
                    )
                }
            }
        }
    }
}
```

---

## Safe Args generated class

Because your nav graph argument is:

```xml
<argument
    android:name="permissionType"
    android:defaultValue="PERMISSION_DEFAULT"
    app:argType="ifac.td.taxi.framework.PermissionRequest$PermissionTypeList" />
```

the generated Safe Args class will be:

```kotlin
PermissionsNavigationFragmentArgs
```

If you keep the fragment name `PermissionsNavigationFragment`, then in the navigation XML you should point to:

```xml
<fragment
    android:id="@+id/permissionsFragment"
    android:name="ifac.td.taxi.ui.screen.PermissionsNavigationFragment"
    android:label="PermissionsNavigationFragment">
```

## Important notes

### 1. Your ViewModel must expose the state used by the composable
The fragment above assumes something like:

```kotlin
val uiState: StateFlow<PermissionsUiState>
fun onEvent(event: PermissionsUiEvent)
```

If your `PermissionsViewModel` currently uses LiveData, you can still adapt it, but since your composable expects `PermissionsUiState`, `StateFlow` is the cleanest option.

---

### 2. Your ViewModel should handle the same logic previously in the old Fragment
The old `PermissionsFragment` had logic for:

- `OnScreenStarted`
- checking permissions on resume
- highlighting a permission
- opening system settings
- opening dialogs
- updating checked/enabled states

That logic should move into the `PermissionsViewModel` and be triggered via `PermissionsUiEvent`.

---

### 3. If you need `onResume()` behavior
Since the composable fragment no longer has the old imperative UI logic, if you still need to refresh permissions when the screen returns to foreground, you can use:

```kotlin
override fun onResume() {
    super.onResume()
    viewModel.onEvent(PermissionsUiEvent.OnScreenResumed)
}
```

Then handle that event in the ViewModel.

Example:

```kotlin
override fun onResume() {
    super.onResume()
    viewModel.onEvent(PermissionsUiEvent.OnScreenResumed)
}
```

## If you want a slightly more complete version

Here is a version with `LaunchedEffect`-style state collection safety and without any app-specific theme assumption beyond Compose:

```kotlin
package ifac.td.taxi.ui.screen

import android.os.Bundle
import android.view.LayoutInflater
import android.view.View
import android.view.ViewGroup
import androidx.compose.runtime.collectAsState
import androidx.compose.runtime.getValue
import androidx.compose.ui.platform.ComposeView
import androidx.compose.ui.platform.ViewCompositionStrategy
import androidx.fragment.app.Fragment
import androidx.fragment.app.viewModels
import androidx.navigation.fragment.navArgs
import ifac.td.taxi.viewmodel.PermissionsViewModel

class PermissionsNavigationFragment : Fragment() {

    private val viewModel: PermissionsViewModel by viewModels()
    private val args: PermissionsNavigationFragmentArgs by navArgs()

    override fun onCreateView(
        inflater: LayoutInflater,
        container: ViewGroup?,
        savedInstanceState: Bundle?
    ): View {
        return ComposeView(requireContext()).apply {
            setViewCompositionStrategy(
                ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed
            )
            setContent {
                val uiState by viewModel.uiState.collectAsState()

                PermissionsScreen(
                    uiState = uiState,
                    safePermissionType = args.permissionType,
                    onEvent = viewModel::onEvent
                )
            }
        }
    }

    override fun onResume() {
        super.onResume()
        viewModel.onEvent(PermissionsUiEvent.OnScreenResumed)
    }
}
```
