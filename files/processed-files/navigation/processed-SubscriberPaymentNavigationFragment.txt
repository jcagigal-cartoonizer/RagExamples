## 3) Important note about arguments
Your old Fragment used `navArgs()`:
```kotlin
private val args: SubscriberPaymentFragmentArgs by navArgs()
```
### Option A: read args in the Fragment and send them to the ViewModel
Example:
```kotlin
val args = SubscriberPaymentNavigationFragmentArgs.fromBundle(requireArguments())
```
Then call something like:
```kotlin
viewModel.init(
    tripId = args.tripId,
    user = args.user,
    subscriber = args.subscriber,
    isFromIngenico = args.isFromIngenico
)
```
### Option B: use a custom ViewModel factory
If the ViewModel needs the nav args at construction time, create it with a factory and keep using `by viewModels { ... }`.

## 4) If you want the Fragment to forward scanner results
```kotlin
onOpenScanner: (cameraPosition: Int, onResult: (String) -> Unit) -> Unit
```
you can connect that to your existing Activity scanner API from the Fragment. For example:
```kotlin
onOpenScanner = { cameraPosition, onResult ->
    (activity as? MainActivity)?.openScanner(
        callback = object : OnScannerResultCallback {
            override fun onSuccess(result: String) {
                onResult(result)
            }
        },
        cameraPosition = cameraPosition
    )
}
```

## 6) One more thing
Your current composable `SubscriberPaymentScreen(...)` already contains navigation side effects like:
That works only if your app is using string routes from Compose Navigation. If you are still using the XML NavController, those routes must exist in your graph or you should change them to `findNavController().navigate(R.id.someFragment)` style navigation.
So for XML navigation, you may need to adapt these effect handlers inside the composable or in the Fragment wrapper.
